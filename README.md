## Анализ архитектуры кода на примере дз-12 (Data Mapper)
- Папка src_before - изначальный код
- Папка src_after - код после рефакторинга

Анализ + шаги исправления:
#### Структура папок.
- Есть реализация Data Mapper и пример, все лежит в 3 папках Console, DataMapper, Example.
- В папке Example структура должна соответствовать приложению, соответственно Console переносим в Example и реализуем там 3 слоя (Domain, Application, Infrastructure).

#### Слой Domain
- Сущности перемещаются в Domain/Entity
- Создаются интерфейсы репозиториев для каждой сущности в Domain/Repository
- Дополнительно, чтобы избежать дублирования кода по DRY, интерфейсы наследуются от базового с минимальным набором функций.

#### Слой Infrastructure
- Реализации интерфейсов репозиториев создаются в папке Infrastructure/Repository
- По аналогии с интерфейсами по Dry, создается абстрактный репозиторий, который реализует базовый интерфейс.
- Папка Console перемешается в Infrastructure

#### Слой Application
- Изначально этот слой отсутствует и смешан с логикой контроллера.
- Выносим логику взаимодействия с сущностями в Application/UseCase.

Изначальная схема:
1. Есть реализация Data Mapper и пример, все лежит в 3 папках Console, DataMapper, Example
2. Example представляет собой просто папку Сущность + репозиторий для каждой сущности
