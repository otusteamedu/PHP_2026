# Система управления событиями на базе Redis

Учебный проект по реализации хранилища событий с системой фильтрации по условиям и приоритетам.

## Архитектура решения

Проект построен по принципам **Clean Architecture**, что обеспечивает выполнение требования о "легкой смене хранилища":

*   **Domain**: `EventDto` — неизменяемый объект данных события.
*   **Contract**: `EventRepositoryInterface` — абстракция, описывающая правила работы с любым хранилищем.
*   **Infrastructure**: `RedisEventRepository` — реализация хранилища под Redis. Использует **инвертированные индексы (Sets)** для быстрого поиска ID событий по критериям.
*   **Service**: `EventFinder` — бизнес-логика, которая получает кандидатов из репозитория и выбирает событие с наивысшим приоритетом.
***Логика поиска**: Для нахождения событий, условия которых являются подмножеством запроса, используется `sUnion` (объединение множеств индексов) с последующей фильтрацией на PHP. Это позволяет корректно обрабатывать случаи, когда у события больше условий, чем в запросе — такие события отсеиваются на этапе фильтрации.

## Особенности реализации Redis

1.  **Rule Engine Logic**: Система находит события, чьи условия являются подмножеством параметров запроса. Поиск оптимизирован через `sUnion` в Redis с финальной проверкой условий на стороне PHP.
2.  **Атомарность**: Сохранение данных и индексов происходит внутри транзакции `MULTI/EXEC`.
3.  **Безопасная очистка**: Метод `clearAll` удаляет только ключи приложения (через реестр `events_registry`), не затрагивая сторонние данные в Redis.
4.  **Безопасность**: Данные сериализуются через `json_encode` с обработкой ошибок; чувствительная информация о подключениях логируется в `error_log` и не выводится пользователю.

## Запуск проекта

1. Сборка и запуск контейнеров:
   ```bash
   docker compose up -d --build
   ```

2. Генерация автозагрузки классов:
   ```bash
   docker compose exec php composer install
   ```

3. Проверка результата:
Открыть в браузере http://localhost
Визуализация данных доступна в RedisInsight по адресу http://localhost:8001

## Примечания по реализации

- **Redis**: ключи индексов хешируются через MD5, что исключает проблемы со спецсимволами и коллизиями. Поиск событий выполняется через `sUnion` с последующей фильтрацией на PHP – это гарантирует корректную логику «условия события являются подмножеством параметров запроса».
- **MongoDB**: для сохранения единообразия логики поиск также реализован через выборку всех документов и фильтрацию на PHP. Это позволяет применять одинаковый алгоритм (subset match) для обоих хранилищ и гарантирует идентичность результатов независимо от выбранной базы данных. При необходимости можно оптимизировать MongoDB-версию через агрегацию без изменения интерфейса.
- **Зависимости**: после запуска контейнеров обязательно выполните `docker compose exec php composer install` для установки библиотеки `mongodb/mongodb`.
