# Название проекта: API сервиса автострахования: расчет, оплата и генерация полисов

## Общее описание системы

Стэк:
- php 8.2
- Laravel 13
- mySQL
- RabbitMQ

Данный проект представляет собой backend-приложение, предоставляющее **RESTful API** для взаимодействия с клиентской частью 

В качестве основного архитектурного паттерна выбран **Модульный монолит**. Вся бизнес-логика приложения строго разделена на независимые доменные модули. 

### Ключевые принципы межмодульного взаимодействия:
* **Прямые вызовы:** Используются для синхронного взаимодействия через строго объявленные контракты.
* **Шина событий:** Применяется для асинхронного, событийно-ориентированного взаимодействия. Модули публикуют события в общую шину, позволяя изолировать побочные эффекты от основного бизнес-процесса.

---

## Структура и зоны ответственности модулей

Приложение разделено на следующие функциональные доменные слои:

### 1. Модуль аутентификации
* **Основная функция:** Единая точка входа для контроля доступа и идентификации пользователей.
* **Обязанности:**
  * Регистрация, авторизация пользователей и управление сессиями.
  * Генерация и подпись JWT-токенов.
  * Валидация прав доступа с помощью глобальных Middleware перед передачей запроса в целевые модули.

### 2. Модуль личного кабинета
* **Основная функция:** Управление профилями пользователей и финансовым балансом.
* **Обязанности:**
  * Хранение и обработка персональных данных клиентов (ФИО, паспортные данные, контакты).
  * Ведение внутреннего виртуального счета клиента для оплаты продуктов.
  * Выполнение операций пополнения счета, проверки лимитов и списания средств по запросу модулей оплаты.

### 3. Модуль проверки авто
* **Основная функция:** Интеграция с внешними источниками данных для валидации ТС.
* **Обязанности:**
  * Изолированное взаимодействие с внешними API (будет фейковая заглушка).
  * Прием внутренних запросов по VIN-коду или государственному номеру.
  * Нормализация ответов и предоставление верифицированных данных для проведения расчетов.

### 4. Модуль расчета
* **Основная функция:** Расчет стоимости страховых продуктов
* **Обязанности:**
  * Агрегация данных о водителе (возраст, стаж, КБМ) и транспортном средстве (марка, модель, год выпуска, мощность).
  * Применение актуальных тарифных сеток, коэффициентов и скидок.
  * Формирование итоговой стоимости, генерация уникального номера черновика полиса и управление его начальными статусами.

### 5. Модуль оформления и оплаты
* **Основная функция:** Оркестрация комплексной бизнес-транзакции покупки полиса.
* **Обязанности:**
  * Проверка валидности и неизменяемости выполненного расчета стоимости.
  * Инициирование транзакции списания средств через биллинг.
  * Передача подтвержденных данных на выпуск финального документа.
  * **Механизм отката:** Реализация компенсирующих действий в случае сбоя на любом из этапов оформления полиса.

### 6. Модуль управления полисами
* **Основная функция:** Сопровождение жизненного цикла страховых договоров.
* **Обязанности:**
  * Ведение реестра оформленных, активных, аннулированных или приостановленных полисов.
  * Предоставление актуальных списков договоров для отображения в личном кабинете.

### 7. Модуль документооборота
* **Основная функция:** Генерация юридических документов и их долгосрочное хранение.
* **Обязанности:**
  * Динамическая сборка и генерация бланков страховых полисов в формате **PDF** на основе метаданных договора.
  * Обеспечение безопасного и надежного хранения сгенерированных файлов файловой системе или S3-совместимом хранилище.

### 8. Модуль уведомлений
* **Основная функция:** Асинхронное информирование пользователей системы.
* **Обязанности:**
  * Работа через внутреннюю систему очередей (например, RabbitMQ или встроенный менеджер очередей фреймворка) для минимизации задержек основного потока выполнения.
  * Подписка на системные события модулей (успешная регистрация, успешная оплата, приближение окончания срока действия полиса).
  * Отправка сообщений по Email.
