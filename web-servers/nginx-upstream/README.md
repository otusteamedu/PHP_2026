# Создать балансируемый кластер

### Основная задача
  - Балансировщик nginx-upstream
  - Балансируемые бэкенды на nginx (у каждого свой php-fpm, в идеале - можно запрашивать любой доступный fpm)
  - Подключите к обоим контейнерам fpm контейнер с Redis
  - Если у Вас есть балансировка, стандартными сессиями уже не обойтись. Иначе не будет работать аутентификация. Переведите хранение сессий в   него
  - Объединить контейнеры Redis в кластер

------------

### Результат

------------
**Запустить Docker и выполнить следующую команду**

```
docker-compose up --build --scale app=3 -d
```

**Описание выполненных работ**

В рамках задачи реализовано следующее:
  1. Настроен балансировщик нагруки
  2. Создана инфраструктура распределенного кэширования и хранения сессий на базе Redis Cluster 7

**Балансировщик**

  - Настроен Nginx для распределения трафика между масштабируемыми контейнерами приложения. Происходит автоматическое перенаправление запросов  только на «живые» контейнеры. Если один из экземпляров PHP-FPM выходит из строя, трафик перераспределяется на остальные.
  - В контейнерах поднимается supervisord (типа sidecar в Kubernetes), который управляет nginx + php-fpm процессами. 
  - Каждый контейнер содержит nginx, php-fpm и php приложение. Масштабирование горизонтальное. 
  - Для хранения сессий используется Redis Cluster. 

**Redis Cluster**

  - Развернут кластер из 3-х независимых мастер-нод Redis в изолированной Docker-сети (back)
  - Реализована система Healthchecks, гарантирующая готовность узлов перед объединением в кластер (иначе не работает)
  - Разработан shell-скрипт для автоматической сборки кластера


  **Безопасность**
    - Внедрена аутентификация через пароли во всей цепочке: от нод до подключений PHP
    - Настроена изоляция Nginx-App-Redis, ограничивающая доступ к данным из внешней сети.
